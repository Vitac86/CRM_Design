# QORT в мастере поручений

Поручение на сделку получает справочные данные через PHP под Windows-учётной записью процесса. Перевод между площадками и вывод на банковский счёт используют карточку субъекта и сохранённые реквизиты CRM. [Открыть мастер](http://127.0.0.1:4179/static-uikit/pages/document-wizard.html?subject=c-006)

## Запуск и остановка

Из корня проекта запустите `order-wizard\serve.cmd` для QORT или `order-wizard\serve.cmd --mock` для тестового справочника. Команда выводит локальный URL. Остановка из консоли — Ctrl+C. Существующий локальный конфиг подключения используется обеими реализациями. [Настройка PHP, порты, запуск и сравнение с Node.js](../../../order-wizard/README.md)

## Как воспроизвести проверки

1. Откройте «Поручение на совершение сделки», выберите фондовый рынок и лимитированное поручение. Поочерёдно введите `RU000A10FAK6`, `YKENP`, `Сбер`. В списке до 20 разных бумаг. Выберите бумагу и сверьте эмитента в карточке.
2. Для `RU000A10FAK6` установите дату заявки 23.11.2026 и срок расчётов «Конкретная дата». Переберите 23, 24, 25 и 26 ноября. В поле НКД показаны сумма на одну бумагу, валюта, дата и источник. Значения контрольного снимка приведены ниже.
3. У этой бумаги текущий номинал 10 000 CNY. Основная секция сообщает цену в CNY и расчёты в RUB. Введите количество, цену в процентах, согласованную вручную сумму в RUB, основание и подтверждение. В PDF проверьте отдельные ячейки цены, НКД, валюты цены и суммы. НКД можно исправить прямо в поле. При необходимости укажите валюту введённого НКД. После смены даты ранее согласованную вручную сумму сделки нужно сверить ещё раз.
4. Для `RU000A10FRA1` на 23.11.2026 при количестве 10 и цене 98,5 % контрольная сумма составляет 9 946,10 RUB. Для муниципального выпуска `RU000A10A6J1` проверьте текущий номинал 300 RUB и доступный НКД. При отсутствии подтверждённого номинала на дату сумму можно согласовать вручную. Выбор T+0, T+1 или T+2 сохраняет срок в PDF. Для загрузки НКД по календарному дню выберите конкретную дату.
5. В поручении перевода выберите одну площадку с обеих сторон. Последний выбор сохраняется, противоположное поле очищается. Выберите разные площадки и укажите сумму. В поручении на вывод выберите готовую банковскую запись в нужной валюте. Скачайте оба PDF и сверьте пропись, код клиента `INV…` и банковский счёт.

## Даты и пересчёт облигации

Дата сделки определяет курс ЦБ. Мастер подставляет дату заявки, пока пользователь сам не выберет дату сделки. Дата расчётов определяет НКД независимо от курса. Для НКД действует порядок секций 1 → 101 → 0. Ноль из секции 1 завершает поиск. При выборе бумаги и даты мастер заполняет поле НКД и показывает источник. После первого редактирования поле сохраняет введённый текст, включая пустую строку, при смене даты, бумаги и при возврате к форме. Запоздавший ответ справочника также сохраняет правку.

Карточка принимает независимые параметры `tradeDate` и `settlementDate`. Для новых поручений мастер передаёт `quotation=percent` и при необходимости валюту введённого НКД `accruedCurrency`. Официальная валютная пара выбирается по `InfoSource = 'MainCurBank'` и валютным ссылкам `TradeAsset_ID` и `PriceAsset_ID` на `Assets.ID`. Архивный день действия хранится в `dbo.CrossRatesHist.OldDate`. Для текущего дня SQL Server допустима запись `dbo.CrossRates` с точно совпадающей `modified_date`. Проверяются положительные совпадающие `Bid` и `Ask` и положительная единица котировки `Qty`. Коды `RUR` в ссылках QORT отображаются как `RUB`.

Курс означает оплату в валюте цены за указанное количество единиц базовой валюты. Для обратной пары мастер делит на нормализованный курс. Для двух иностранных валют допустим пересчёт через RUB по двум официальным котировкам одной даты. При пропуске, конфликтующих котировках или ошибке чтения мастер показывает причину и принимает ручной курс в валюте расчётов за одну единицу исходной валюты. Ручной курс привязан к бумаге, дате сделки и валютной паре. Курсы соседних дней и рыночные котировки не используются.

В новом поручении цена облигации задаётся в процентах от номинала. Для проверки шага цены используются согласованные признаки торговой секции и инструмента QORT. Чистая стоимость и НКД в разных валютах конвертируются отдельно. Итог округляется один раз по разрядности валюты платежа.

Число с запятой или точкой в поле НКД сразу участвует в расчёте. При вводе текста, например «По договору», или при очистке поля автоматическая сумма исчезает. Согласованную сумму можно указать и подтвердить отдельно. В PDF сохраняются введённый НКД и согласованная сумма. Действующая проверка размещения по-прежнему применяется к тексту при печати.

### Контрольный пример RU000A10A869

Укажите сделку 23.11.2026, расчёты 24.11.2026, количество 1 330 и цену 108. У выпуска номинал 1 000 USD. НКД из QORT составляет 53,129999 USD на бумагу, в мастере и PDF показывается 53,13. Официальный курс в контрольном срезе составил 82,1911 RUB за 1 USD.

В срезе 23.11.2026 секция 1 возвращала из таблицы `MarketInfo` 53,129999 USD, а архив секции 101 — 53,13 USD. В срезе 24.11.2026 значение секции 1 перешло в `MarketInfoHist`. Мастер в обоих случаях выбирает 53,129999 USD из секции 1.

| Значение НКД для расчёта | Цена | К оплате, RUB |
| --- | ---: | ---: |
| Исходное из QORT, 53,129999 USD | 108 % | 123 867 157,41 |
| Введено оператором, 53,13 USD | 108 % | 123 867 157,52 |

Для проверки архива смените только дату сделки на 20.11.2026. Курс изменится на 81,929 RUB за 1 USD, НКД останется на 24 ноября. В срезе 23 ноября курса на 24 ноября ещё не было. При выборе 24 ноября датой сделки ручной курс 80,12 при цене 108 % и исходном НКД дал 120 745 879,44 RUB. После появления официального курса для воспроизведения ручного сценария выберите день без записи в QORT. [История USD Банка России](https://www.cbr.ru/eng/currency_base/dynamics/?UniDbQuery.Posted=True&UniDbQuery.VAL_NM_RQ=R01235)

## Чтение данных

| Запрос | Данные и условия |
| --- | --- |
| Поиск `GET /api/order-reference/assets` | Параметризованный поиск в `Assets` и `Securities.SecCode` от двух символов. Ранжирование по точному ISIN, точному коду, префиксу кода, префиксу имени и частичному имени. Группировка по `Assets.ID` до пагинации, затем добавляются эмитент из `Firms` и торговый код. |
| Карточка `GET /api/order-reference/assets/{id}` | Одна бумага, эмитент, торговые коды и секции. Вид бумаги из классификации QORT, единицы котировки из `Securities.IsProcent` и `MarketInfo.IsProcent`, шаг из `MarketInfo.TickSize`. Валюты цены и расчётов из валютных ссылок, включая `MarketInfo.PriceAsset_ID` и `PayAsset_ID`. Текущий номинал и его валюта из `Assets`. Неизвестная ссылка `-1` остаётся неопределённой. |
| Та же карточка с `settlementDate=YYYY-MM-DD` | Для облигации читается `SettleDateAccrued` на точный `SettleDate`. Сначала секция 1, при NULL или отсутствии значения затем 101. В каждой секции приоритет у `MarketInfo`, затем у `MarketInfoHist` с максимальными допустимыми `OldDate` и `ID`. Реальный ноль завершает поиск. Если обе секции пусты, источник получает статус `DEFAULT_ZERO`. Дата среза берётся из SQL Server один раз при чтении карточки. |
| Номинал и итог | Датированное значение из `AssetsBaseValues` проверяется на точное совпадение даты. На дату среза допускается положительный текущий номинал действующего выпуска при совпадении с исходным и отсутствии признака индексации. Для обычной неиндексируемой облигации с погашением номинала целиком (атрибут F в пятой позиции CFI) совпадающие текущий и исходный номиналы также применимы между выпуском и погашением. Датированная запись имеет приоритет. Нулевые и противоречивые датированные значения требуют ручного ввода. Для подтверждённой чистой процентной котировки мастер добавляет НКД один раз. Для отображения НКД округляется по валюте. В денежной формуле используется значение до округления для печати. |

Статусы источника, дата среза, дата наблюдения архива, выбранная секция и исходное значение НКД возвращаются в `bondData`. Выбранный пользователем НКД и согласованная сумма попадают в PDF. Индексы проверены через `sys.index_columns`. Ключ текущих рыночных данных начинается с секции и актива, у архива есть индекс по этой же паре. Каждый SQL-файл приложения содержит только SELECT с параметрами или CTE с завершающим SELECT.

## Правила, требующие подтверждения владельца данных

- Какая договорная формула действует для специальных выпусков с отдельной валютной оговоркой? Для обычной конвертации утверждена дата сделки.
- Как подтверждать номинал на произвольную дату при амортизации или индексации, когда для даты отсутствует однозначная запись `AssetsBaseValues`?
- Какой реквизит QORT подтверждает включение НКД для нестандартной денежной котировки и валюту НКД при расхождении источников? До подтверждения доступна ручная сумма.
- Какой торговый календарь и режим использовать, если фактическую дату НКД понадобится выводить из T+N?
